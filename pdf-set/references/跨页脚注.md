## 输入/输出

- 输入：`ocr-result/` 中按页码命名的初步 OCR Markdown 文件。
- 输入：`images/` 中同页码的 jpg/jpeg/png/bmp/tif/tiff/webp 图片。
- 输出：直接写回 `ocr-result/`。
  - 未涉及跨页脚注的页：保持原 `页码.md` 不变。
  - 涉及跨页脚注的连续页：在 `ocr-result/` 内写入 `起始页-结束页.md`，例如 `3-5.md`。
  - 原范围内的单页文件会移动到 `ocr-result/_footnote_backup/<timestamp>/`，避免后续排版成书重复拼接。

## 阶段 1：确定目标范围

1. 扫描 `ocr-result/` 中的数字页码 Markdown 文件。
2. 按页码顺序判断跨页承接：
   - 若前页有 `⬇️` 或后页有 `⬆️`，生成两页范围。
   - 若范围末页仍有 `⬇️`，继续向后扩展。
   - 若前页有 `⬇️` 而下一页没有 `⬆️`，但再后面的连续页有 `⬆️`，扩展到该页。
3. 每个连续承接范围写回 `ocr-result/起始页-结束页.md`。

## 阶段 2：上传图片和初步 OCR 结果

脚本会把目标范围内每一页的图片、对应 `ocr-result/页码.md` 内容、`footnote_continuation_prompt.md`、以及 `ocr_prompt.md` 一起发送给模型。

给模型的任务边界：

- 只对 `处理脚注 Footnote：转移` 做进一步处理。
- 重点检查含有 `⬆️` 和 `⬇️` 的段落。
- 再结合图片中字型大小判断是否还有脚注被误当作正文。
- 只合并跨页脚注，不许补充内容，不许删改正文，不许润色，不许翻译。

## 阶段 3：本地验证与重试

1. 脚本会比较处理前后文本。
2. 校验时忽略空白、标点、emoji 和 `<sup>` 等 HTML 标签差异。
3. 规范化后的字符必须完全一致；不一致就把差异反馈给模型并重试。
4. 超过 `--max-retries` 仍不一致时，脚本报错停止，等待人工介入。
